# Trellis Forge — AI 3D model studio on NVIDIA NIM

Turn a sentence or a photo into a **textured, game-ready 3D model (GLB)**. This studio uses the free
hosted NVIDIA NIM endpoints:

| Stage | Model | What it does |
| --- | --- | --- |
| 3D lift | `microsoft/trellis` (TRELLIS image-large 1.2B / text-large 1.1B) | Image **or** text → GLB mesh with baked PBR materials |
| Concept render | `black-forest-labs/flux.1-schnell` | Text → 1024² product shot used as the TRELLIS input |
| Concept render (alt) | `black-forest-labs/flux.1-dev` | Higher-fidelity concept render (slower) |

NVIDIA hosts these models for free during prototyping — one `nvapi-…` key from
[build.nvidia.com](https://build.nvidia.com/settings/api-keys) unlocks all of them. The key only ever lives
on the server: it is read from the Vercel environment and never shipped to the browser.

---

## Features

- **Three generation routes**
  - **Prompt → concept → 3D** — FLUX paints a centred product shot, TRELLIS lifts it (best quality).
  - **Prompt → 3D** — TRELLIS text-large straight from the prompt (fastest).
  - **Image → 3D** — drop, browse or paste a photo, TRELLIS reconstructs the object.
- **Inputs are prepared for you** — every upload is fitted to a 1 MP square (TRELLIS's documented
  sweet spot), and an auto-matte removes the background, a planet, stars and other scenery by keeping the
  centred object's connected components. The panel shows *exactly* what TRELLIS will see, before you spend a call.
- **Filters on the reference image** — presets (Studio / Clean cut / Rescue dark / Silhouette / Raw) plus
  fine-tune sliders for auto-levels, exposure, contrast, saturation, sharpen and backdrop colour. Filters
  always re-process from the original file (never stacked), run entirely in the browser, and the preview
  updates to the exact JPEG that will be sent.
- **Multi-view lifts** — add up to two extra views (front / top / side). TRELLIS averages up to 8 views,
  which is the single biggest quality win on elongated subjects like ships.
- **Real 3D viewport** — three.js + PBR environment lighting, orbit/zoom, auto-rotate, ground grid,
  textured / clay / wireframe modes, live triangle + vertex counts.
- **Multi-format export** (Meshy/Tripo-style) — from the single GLB TRELLIS returns, the studio converts in
  the browser to **GLB, OBJ, STL, PLY or USDZ** (AR Quick Look), with an optional **35 % low-poly / LOD**
  decimation via meshoptimizer. No extra API calls.
- **Turntable PNG capture** — one click saves four 90°-apart viewport renders for docs, marketplaces or a
  quick contact sheet.
- **AI prompt enhance** — rewrites a thin prompt (`a starship`) into a shape-first description using a hosted
  chat NIM (default `meta/llama-3.1-8b-instruct`). If the key is missing, rate-limited or offline, it
  silently falls back to a local composer that adds form/material/quality words instead of failing the click.
- **Quality tiers** — Draft 15 / Standard 25 / High 35 sampling steps, Meshy-style.
- **Tune the sampler** — seed, latent/sparse steps, both CFG scales, plus a concept-model switch.
- **Session gallery** — every generated asset stays in memory for the tab's lifetime, one click to reload.
- **Variations** — one button re-runs the same prompt with a fresh seed (⌘/Ctrl + ↵ in the prompt box).
- **Honest failure states** — missing key, rate limits, content filters, NVIDIA-side 5xx and function
  timeouts each get their own message with a fix, plus the `nvcf-reqid` for NVIDIA support.
- **Bundled sample asset** so the viewport is never empty (generated by `npm run make:demo`).

## Quick start

```bash
git clone https://github.com/Ghanimsokaki/trellis.git
cd trellis
npm install
cp .env.example .env.local        # paste your nvapi-… key
npm run dev                       # http://localhost:3000
```

Until a key is present the UI stays readable and you can still explore the viewport with the bundled
sample asset (the **Load sample asset** button) — generation simply stays disabled.

Get a free key: <https://build.nvidia.com/settings/api-keys> (Settings → API Keys → Generate API Key).
A key works across the whole hosted catalog; usage is capped by per-model rate limits instead of credits.

## Deploy to Vercel

1. Push this repo to GitHub (or use the button below).
2. **Project → Settings → Environment Variables** → add:

   | Name | Value | Environments |
   | --- | --- | --- |
   | `NVIDIA_API_KEY` | `nvapi-…` | Production, Preview, Development |

3. Redeploy.

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FGhanimsokaki%2Ftrellis&env=NVIDIA_API_KEY&envDescription=NVIDIA%20NIM%20API%20key%20from%20build.nvidia.com&envLink=https%3A%2F%2Fbuild.nvidia.com%2Fsettings%2Fapi-keys&project-name=trellis-forge)

or from the CLI:

```bash
npm i -g vercel
vercel
vercel env add NVIDIA_API_KEY production   # paste the key when prompted
vercel --prod
```

No `vercel.json` is required — Next.js is detected automatically and every NIM call happens inside a
Node.js route handler.

> **Vercel plan note.** `app/api/generate/route.ts` sets `maxDuration = 300` because a TRELLIS lift can take
> 20–90 s. Hobby caps function duration at 60 s; Pro and Enterprise allow 300 s. If you stay on Hobby, raise
> the plan, self-host TRELLIS (see below), or expect occasional `504` timeouts on heavy prompts.

## The multi-layer forge

NVIDIA's hosted TRELLIS preview is explicit in its schema: *"Preview API NIM supports only a predefined set of
images. The image should be in form of `data:image/png;example_id,{example_id}` with example_id in a range
[0,3]"*. Inline base64 and NVCF assets are both rejected with `422 Expected: example_id`. A user photo therefore
cannot be lifted to a mesh on the hosted endpoint — so the app runs it through layers instead of failing:

| Layer | What it does | Model |
| --- | --- | --- |
| **Perceive** | Reads the photo: subject, silhouette, parts, palette, plus a ≤77-char prompt and web queries | `meta/llama-3.2-11b-vision-instruct` (chat NIM) |
| **Resolve** | Searches the web for more references and matching 3D models (Brave / Tavily / Serper, or keyless DuckDuckGo) | search provider, optional |
| **Forge** | TRELLIS image mode with the photo (self-hosted only), else TRELLIS text mode on the description | `microsoft/trellis` |
| **Report** | Route, fidelity, per-layer timings and the references found, shown in the viewport | — |

Fidelity is reported, not implied:

- **photo-exact** — `NVIDIA_TRELLIS_INFER_URL` points at your own TRELLIS NIM; the photo (and any extra views)
  condition the mesh.
- **from description** — hosted preview; the vision layer's description drives a text-mode mesh.
- **prompt → mesh** — text-only generation.

The forge also clamps every prompt to TRELLIS' 77-character limit, keeps a 422 from the image branch as a signal
to switch to the caption bridge (`NVIDIA_TRELLIS_IMAGE_MODE=always` opts into trying image mode on the hosted
gateway), and degrades the vision layer to your written brief if the chat model is unavailable.

## How it works

```
browser ──► /api/concept ──► ai.api.nvidia.com/v1/genai/black-forest-labs/flux.1-schnell
                                   │ 1024² JPEG (data URL)
                                   ▼
browser ──► /api/generate ──► ai.api.nvidia.com/v1/genai/microsoft/trellis
                                   │ { artifacts: [{ base64: <GLB>, seed, finishReason }] }
                                   ▼
                        model/gltf-binary response + X-Trellis-Meta
```

| Route | Body | Response |
| --- | --- | --- |
| `GET /api/health` | — | `{ configured, authVariable, trellisModel, imageModel, imageModels, apiBase, maxDurationSeconds }` |
| `POST /api/concept` | `{ prompt, settings, imageModel }` | `{ image, prompt, rawPrompt, seed, model, elapsedMs }` |
| `POST /api/enhance` | `{ prompt, offline? }` | `{ prompt, original, model, elapsedMs, offline, addedShapeWords, fallbackReason? }` — always `200`: the LLM path degrades to the offline composer |
| `POST /api/generate` | `{ mode: "text" \| "image", prompt?, image?, engine, imageModel?, conceptPrompt?, settings }` | binary **GLB** (`model/gltf-binary`) with generation metadata in `X-Trellis-Meta` (base64 JSON) |

TRELLIS request fields map straight to the NIM schema: `mode`, `image`/`prompt`, `seed`,
`slat_cfg_scale`, `ss_cfg_scale`, `slat_sampling_steps`, `ss_sampling_steps`.

## Limits & good to know

- **Vercel body limits.** Serverless request/response bodies cap at 4.5 MB. Uploads are auto-downscaled to
  1024 px JPEG, and the concept render is kept under ~3.6 MB. Very detailed TRELLIS assets can still exceed
  the response cap — download from the viewport immediately if that happens, or run the app on a Node host.
- **Rate limits, not credits.** Free hosted NIM is rate-limited per model; the UI surfaces `429`s with a retry hint.
- **Best inputs.** One object, plain background, three-quarter view. TRELLIS is trained on isolated assets,
  not scenes; text-to-3D (direct) is noticeably weaker than image-conditioned generation.
- **Trial terms.** Hosted NIM calls are governed by the NVIDIA API Trial Terms of Service and the model's
  license (TRELLIS: MIT / NVIDIA Community Model License). Production use requires NVIDIA AI Enterprise.
- **Reference images go through NVCF assets.** Hosted functions cap inline base64 at roughly 180 KB, and the
  hosted TRELLIS gateway rejects oversized data URLs with `Expected: example_id, got: base64`. Every upload is
  therefore pushed to NVIDIA's own asset store first (`POST /v2/nvcf/assets` → presigned `PUT`) and sent as
  `data:image/jpeg;asset_id,<uuid>` with an `NVCF-INPUT-ASSET-REFERENCES` header. Self-hosted containers keep
  using plain base64. Assets are NVIDIA-managed and short-lived; nothing touches a third-party bucket.
- **No storage.** Generated meshes live only in the browser tab.
- **Self-hosting.** With an NGC key you can run the TRELLIS NIM container on your own GPU and set
  `NVIDIA_TRELLIS_INFER_URL=http://localhost:8000/v1/infer` to bypass the hosted gateway entirely.
- If NVIDIA's hosted TRELLIS function is having a bad day (it happens), the studio tells you and points at
  the alternate engine instead of failing silently.

## When NVIDIA says no

The studio reports NVIDIA's own validation text (the `detail` field) in the error card and in
`console.error`, with the `nvcf-reqid` for support tickets.

| Symptom | Cause | Fix shipped here |
| --- | --- | --- |
| `422` / "could not use the request payload" | The hosted gateway validates stricter than the container docs. Extra fields (`mode`, tuned CFG/steps) can be rejected. | Requests start from the documented minimal body (`image`/`prompt` + `seed`) and only add fields you actually changed. On a 400/422 the client retries a set of progressively smaller payloads and reports which one worked. |
| `422` after touching CFG | `slat_cfg_scale` / `ss_cfg_scale` are `exclusiveMinimum: 1.0`, so `1` is invalid. | Both are clamped to `1.05 … 10` server-side; the sliders can no longer produce an invalid value. |
| Mesh looks like a cousin of the photo, not a twin | The hosted preview refuses user photos, so the forge builds from the vision layer's description. | The layer report labels the asset **from description**. Set `NVIDIA_TRELLIS_INFER_URL` to your own TRELLIS NIM for photo-exact meshes. |
| `422` `Expected: example_id, got: base64` | The hosted gateway wants an NVCF asset reference, not an inline data URL (or the function only exposes catalog examples for that account). | Images are uploaded to NVCF asset storage automatically and referenced by id; if the gateway still refuses, the error card explains the three escape hatches (self-host, Direct text → 3D, playground). |
| `422` on a big upload | TRELLIS expects ~1 MP. A 597×335 screenshot is 0.2 MP and not square. | Uploads are re-fitted into a 1024² JPEG (upscaling allowed) before sending. |
| `422`/weird mesh from a scene photo | Background, planet, glows confuse the reconstruction. | Auto-matte keeps the centred object only; toggle it off to send the raw frame. The preview shows the difference. |
| Dark or busy screenshot lifts badly | Low contrast hides hull detail, and a planet/starfield competes with the subject. | Filter presets + percentile auto-levels + auto-matte. The stretch is 2 %/98 % and skips near-flat images, so it cannot amplify noise. |
| `504` / "ran past the function time limit" | Vercel stops functions at 60 s on Hobby (300 s on Pro). TRELLIS can take 20–90 s. | The studio retries once automatically at **Fast 15** steps, and the Speed preset lets you pick 15 / 25 / 35 up front. |
| `429` | Hosted NIM rate limit per model. | One automatic retry with backoff, then a message with a wait hint. |
| `CONTENT_FILTERED` | Prompt tripped the safety checker. | Surfaced as its own error with rewrite advice. |
| Enhance came back "expanded locally" | The chat NIM was rate-limited, unreachable, or no key is set. | Intentional: the route returns `200` with `offline: true` and a `fallbackReason` instead of an error. |
| USDZ export fails | USDZ packaging needs a full canvas/WebGL context. | The menu shows the failure; use GLB or OBJ instead. |

### Prompting 3D subjects (ships, vehicles, props)

- Describe **shape**, not lore: `oval saucer hull, two nacelles on straight angled pylons, glowing blue vents`
  beats `USS Enterprise NCC-1701`.
- One object, plain background, three-quarter view, slightly above the horizon — the app appends these
  constraints to the concept render for you.
- Names, registry decals, crew, nebulas, "in orbit", "at warp" and explosion effects all hurt.
- Judge geometry in **Clay** mode, then fix pylon junctions in Blender; those fusions are a property of
  the model, not a bug in the app.
